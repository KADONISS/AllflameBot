# Knowledge Roadmap

## Purpose

Record likely knowledge improvements without presenting them as committed code
work.

## Audience

Maintainers and agents planning future work.

## Update when

Update when a roadmap item is completed, rejected or reprioritized.

## Candidate work

- Validate and document the terrain coordinate transform at runtime.
- Connect or remove settings whose runtime consumers are unclear.
- Split the monolith by logical boundary while preserving one assembly.
- Add deterministic planner/state/normalization tests and fixtures.
- Make dependency metadata in `3rdparty.json` match the project contract.
- Add a deterministic build script and CI when the DPB dependency environment
  can be provided safely.

These are candidates, not claims that implementation exists.
